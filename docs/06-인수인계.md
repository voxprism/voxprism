## 2. 새 PC·새 세션에서 시작하기

```bash
git clone https://github.com/voxprism/voxprism.git && cd voxprism
./scripts/setup-dev.sh                                   # git 훅·커밋 틀
python3 -m venv .venv && . .venv/bin/activate && pip install -r app/requirements-ci.txt
cd app && python -m pytest -q tests && cd ..             # 12 passed
```

서버를 다루려면 저장소 밖에 있는 파일 4가지를 원래 PC에서 **직접** 옮겨 와야 합니다(채팅·메일·저장소로 보내지 않기).

| 파일 | 내용 | 없으면 |
| --- | --- | --- |
| `secrets/keys.env` | NCP·CLOVA·HF 키 | `infra/keys.env.example`로 새로 만들고 콘솔에서 발급 |
| `secrets/web_login.txt` | 웹 비밀번호·세션 키 | `deploy.sh`가 새로 만듦(로그인 비밀번호가 바뀜) |
| `secrets/whosaid_ed25519`, `known_hosts` | 서버 SSH 키 | 서버에 새 키 등록 필요(콘솔 › 서버 › 관리자 비밀번호로 접속) |
| `infra/state.env` | 자원 번호·IP | `infra/state.env.example`에 콘솔 값을 채움 |

ncloud CLI는 저장소에 없습니다(약 265MB). [CLI 안내 페이지](https://cli.ncloud-docs.com/docs/guide-clichange)에서 1.1.30을 받아 `tools/ncloud-cli/`에 풀고, 인증 파일은 **값이 화면에 나오지 않게** 만듭니다:

```bash
set -a; . secrets/keys.env; set +a
mkdir -p ~/.ncloud && (umask 077; printf '[DEFAULT]\nncloud_access_key_id = %s\nncloud_secret_access_key = %s\nncloud_api_url = https://ncloud.apigw.ntruss.com\n' \
  "$NCLOUD_ACCESS_KEY" "$NCLOUD_SECRET_KEY" > ~/.ncloud/configure)
./infra/server.sh status
```

## 4. 운영 메모

- **공인 IP가 바뀐 곳에서 SSH:** ACG `whosaid-acg`의 22번 규칙은 만들 때의 공인 IP 하나만 허용합니다. 콘솔 › Server › ACG › `whosaid-acg` › Inbound에 새 IP/32를 추가하거나, CLI `vserver addAccessControlGroupInboundRule`(규칙: TCP, 22, `<새 IP>/32`)을 씁니다. `state.env`의 `MYIP`도 고칩니다. 웹(80)은 어디서나 열립니다.
- **서버 재시작:** 서비스는 부팅 시 자동으로 올라오고, 처리 중이던 작업은 한 번 다시 대기열에 들어갑니다(FR-JOB-07). 첫 작업은 모델을 메모리에 올리느라 조금 늦습니다.
- **로그인 비밀번호 바꾸기:** `secrets/web_login.txt`의 `password=` 줄을 바꾸고 `./infra/deploy.sh code`. 세션 키(`session_secret`)를 바꾸면 모든 사람이 다시 로그인해야 합니다.
- **소리 자막 켜기:** CLOVA Speech 콘솔에서 도메인의 이벤트 탐지를 켜면 코드 변경 없이 동작합니다(`WHOSAID_CLOVA_SED=auto`). 워커가 '미지원'을 기억하므로 켠 뒤 `sudo systemctl restart whosaid-worker`.
- **키 정리:** NCP API 키는 계정 전체 권한입니다. 프로젝트가 끝나면 콘솔에서 사용 중지·삭제합니다.

## 5. 평가 다시 돌리기

파이프라인(SPEC-002·003)을 바꾸는 PR에는 전후 수치가 필요합니다(NFR-QUAL-01). 서버에서:

```bash
cd /opt/whosaid/app && PY=/opt/whosaid/venv/bin/python
# 1) (이미 있음) 테스트 영상: /srv/whosaid/testset/test_{3spk_seed7,3spk_seed11,4spk_seed5}.{mp4,truth.json}
#    새로 만들려면: $PY tools/make_test_set.py --parquet /srv/whosaid/testset/zeroth_test.parquet --out /srv/whosaid/testset --speakers 3 --seed 7
# 2) 웹에서 업로드(출연자 수 입력/자동 × 복원 켬/끔) 또는 curl -u x:<비밀번호> -F file=@… http://localhost:8000/api/jobs
# 3) 지표
$PY tools/evaluate.py --truth /srv/whosaid/testset/test_3spk_seed7.truth.json \
   --baseline-asr /srv/whosaid/data/jobs/<id>/asr.json --result /srv/whosaid/data/jobs/<id>/result.json
# 4) 여러 실행 묶기: $PY tools/eval_runs.py runs.json --out eval.json
```

결과 표를 PR 본문에 붙이고, 기준선이 바뀌면 `docs/eval_v2.json` 갱신과 [SPEC-007](../specs/007-evaluation/spec.md) 6절 표를 고칩니다.

## 9. 알려진 문제·주의

- 출연자 수를 자동으로 두면 화자를 적게 잡습니다(평가 3개 중 2개) → 업로드 화면 안내 문구로 입력을 권장 중.
- 겹친 구간 오인식, 짧은 복원 조각이 다른 화자에게 붙는 경우가 남아 있습니다.
- 3명 이상 동시 발화는 2명만 복원합니다.
- HTTP만 지원합니다. 비밀번호는 시연용으로만.
- 서버 `apt`에서 nginx 설치 후처리가 IPv6 때문에 실패할 수 있습니다(setup 스크립트가 우회). 서버를 새로 만들 때 참고.
- 화면 분석 모델은 `/srv/whosaid/models/vision`(3개). 새 서버는 `setup`이, 기존 서버는 `./infra/deploy.sh deps`가 준비합니다.
- faster-whisper 1.2.1은 PyAV 19와 맞지 않아(경로 입력 시 `metadata_errors` 오류) 배열로 넘기도록 고쳤습니다(D-13). Whisper 대체 엔진은 이 수정 전까지 서버에서 실패하고 있었습니다.
- uv가 CUDA용 torch를 받지 않도록 `torch==2.9.1+cpu`로 고정돼 있습니다. 의존성을 올릴 때 이 고정을 같이 확인합니다.
