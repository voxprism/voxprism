## 1. 한 줄 요약

영상을 올리면 **지금 말하는 사람을 영상 속에서 화자 색 윤곽으로 강조**하고, **같은 색 윤곽의 자막**을 화면 위쪽에 띄워
청각장애인이 "누가 무슨 말을 하는지" 한눈에 알 수 있게 하는 웹 서비스입니다. 화면 밖에서 말하는 사람은 자막에
'화면 밖'으로 알리고, 두 사람이 **동시에 말해 묻힌 말도** 목소리별로 분리해 보여 줍니다.

## 2. 문제

| 문제 | 지금 일어나는 일 |
| --- | --- |
| 누가 말했는지 모른다 | 유튜브 자동 자막과 대부분의 클립 자막에는 화자 표시가 없다. 4~7명이 끼어드는 예능에서는 입 모양과 타이밍으로 화자를 추측해야 해서 금방 지친다. |
| 동시에 말하면 말이 사라진다 | 음성 인식은 겹친 구간에서 큰 목소리 한쪽만 받아 적거나 두 문장을 섞는다. 맞장구·끼어들기·리액션처럼 예능의 재미를 만드는 말이 가장 먼저 빠진다. |
| 사람이 만든 폐쇄자막은 드물다 | 본방송 밖의 클립·개인 영상에는 화자 표시 자막이 거의 없다. |
| 이름표만으로는 화면 속 누구인지 모른다 | '화자 2'라는 글자를 읽고 다시 화면에서 그 사람을 찾아야 한다. 출연자를 모르는 시청자는 이름표와 얼굴을 연결할 수 없다. |
| 화면 밖 목소리 | 내레이션·제작진·화면에 잡히지 않은 출연자의 말은 누가 했는지, 화면 속 누군가가 한 말인지 알 수 없다. |
| 잡음이 자막이 된다 | 박수·웃음·배경음이 엉뚱한 글자나 가짜 화자로 잡혀 자막을 어지럽힌다. |

대상 규모: 2024년 말 등록장애인 263만 1,356명 중 청각장애가 16.8%로 약 44만 명입니다([보건복지부 2024년도 등록장애인 현황, 뉴데일리 보도](https://www.newdaily.co.kr/site/data/html/2026/03/18/2026031800235.amp.html)). 소리를 끄고 보는 사람과 한국어 학습자도 같은 문제를 겪습니다.

## 3. 사용자

| 페르소나 | 상황 | 바라는 것 |
| --- | --- | --- |
| P1 청각장애인 시청자 | 예능 클립을 자막에 의존해 본다 | 누가 말했는지 바로 알고, 겹친 말도 놓치지 않기 |
| P2 난청인·고령 시청자 | 소리는 들리지만 겹치면 못 알아듣는다 | 크게, 오래, 화자별로 구분된 자막 |
| P3 영상 제작자·자막 봉사자 | 화자 자막을 손으로 단다 | 초안을 자동으로 받고 이름만 고치기 |

## 4. 목표와 성공 지표

**MVP 목표:** 5분짜리 다인 대화 영상을 올리면 10분 안에 화자별 자막과 겹친 말 복원 결과를 보여 준다.

**v2 목표:** 같은 영상에서 화면에 나온 화자는 말하는 동안 영상 속 윤곽으로 강조되고, 화면 밖 말은 '화면 밖'으로 표시된다.

| 지표 | 목표 | 현재(2026-11-18) | 측정 |
| --- | --- | --- | --- |
| 화자별 글자 오류율 cpCER (출연자 수 입력) | ≤ 0.40 | **0.344** | 합성 평가셋 v2, [평가 스펙](../specs/007-evaluation/spec.md) |
| 겹친 발화 재현율 | ≥ 0.70 | **0.752** | 위와 같음 |
| 사라진 겹친 발화 (35개 중) | ≤ 5 | **3** (일반 자막 28) | 위와 같음 |
| 처리 시간 / 영상 길이 | ≤ 1.5배 (v2: 화면 분석 포함 ≤ 2.0배) | **약 1.2배** (복원 끄면 0.6배) | 배포 서버 c8-g3 실측 |
| 얼굴–목소리 연결 정확도 (v2) | 연결한 쌍의 ≥ 90%가 맞음, 확신 없으면 연결하지 않음 | 측정 전 | 사람이 확인한 실제 영상(SPEC-009 평가) |
| 말하는 사람 강조 정밀도 (v2) | 강조된 프레임의 ≥ 85%가 실제로 그 사람이 말하는 장면 | 측정 전 | 위와 같음, 샘플 프레임 육안 판정 |

## 5. 범위

| 영역 | MVP에 포함 | 다음 단계로 미룸 |
| --- | --- | --- |
| 입력 | 영상·음성 파일 업로드(최대 20분, 1GB) | 유튜브 링크 가져오기(저작권·약관) |
| 음성 인식 | 한국어, CLOVA Speech 우선 + Whisper 대체 | 다국어, 실시간 스트리밍 |
| 화자 | 목소리로 구분, 사람이 이름 붙이기·합치기. **v2: 얼굴과 목소리 자동 연결(영상 한 편 안에서)** | 영상 사이에 사람 기억, 얼굴로 자동 이름(출연자 DB) |
| 겹친 말 | 2명 동시 발화 분리·재인식·복원 | 3명 이상 동시 발화 |
| 표시 | 이름표+색 자막, 겹치면 줄을 나눠 동시 표시, 소리 자막. **v2: 말하는 사람 윤곽 강조, 자막 위쪽 고정·윤곽색 일치, '화면 밖' 표시** | 말한 사람 얼굴 옆 말풍선(자막 위치가 움직임) |
| 잡음 | **v2: 낮은 신뢰도의 짧은 인식, 잠깐만 잡힌 가짜 화자 걸러내기** | 잡음 제거 모델(Demucs 등) |
| 출력 | 웹 플레이어, SRT·VTT·ASS·JSON, 자막 입힌 MP4 | 브라우저 확장(유튜브 위 표시) |

**하지 않는 것:** 회원가입·다중 사용자 권한, 결제, 공개 공유 링크, 모바일 앱.

## 6. 핵심 사용자 흐름

1. **올리기** — 파일, 제목, 출연자 수(모르면 자동), '겹친 말 복원'·'소리 자막'을 고른다.
2. **기다리기** — 준비 → 음성 인식 → 화자 구분 → 겹친 말 복원 → 자막 생성 진행률을 본다. 페이지를 닫아도 서버가 계속 처리한다.
3. **이름 붙이기** — 화자 카드의 장면 3장과 대표 대사를 보고 이름을 적는다. 한 사람이 둘로 나뉘었으면 '합치기'.
4. **보기** — 말하는 사람이 영상 속에서 화자 색 윤곽으로 빛나고, 같은 색 윤곽의 자막이 화면 위쪽 정해진 줄에 뜬다.
   화면 밖 말은 자막에 '화면 밖'이 붙는다. 동시에 말하면 줄을 나눠 함께 뜬다. 글자 크기·전체 화면·대본 클릭 이동.
5. **내려받기** — SRT·VTT, ASS(화자 색 유지), 자막 입힌 MP4.

## 8. 제약과 원칙

- **소버린 AI:** 한국어 인식은 국내 클라우드의 국내 모델(네이버 클라우드 CLOVA Speech)에 맡기고, 화자 분리·음원 분리·얼굴·사람 찾기 모델은 서버 안에서 돌린다. 영상이 외부로 나가는 경로는 CLOVA Speech 인식 요청 하나뿐이다. 얼굴 특징값은 작업 폴더 밖으로 나가지 않고 작업과 함께 지워진다.
- **서버 1대:** NCP c8-g3(vCPU 8, 16GB, GPU 없음) 한 대에서 웹·워커·nginx가 함께 돈다.
- **비용:** 서버+SSD 약 408원/시간(VAT 별도). 시연·실험 때만 켠다.
- **저작권:** 업로드 영상은 개인 시청용 처리로 한정하고 로그인 뒤에만 보인다.

## 9. 위험

| 위험 | 영향 | 대응 |
| --- | --- | --- |
| 실제 예능의 배경음악·웃음소리에서 분리 품질 저하 | 복원 문장이 틀리거나 빠짐 | 실제 클립 평가, 분리 전 보컬 추출(Demucs) 실험 |
| 출연자 수 자동 추정 오류 | 화자가 합쳐짐 | 업로드 화면에서 입력 권장(자동일 때보다 오류 약 1/3 감소) |
| 3명 이상 동시 발화 | 2명만 복원 | 3화자 분리 모델 검토 |
| 짧은 맞장구('응'·'아') | 인식 자체가 어려움 | 소리 자막([맞장구])으로 표시 검토 |
| 이름은 사람이 붙여야 함 | 업로드한 사람의 수고 | 얼굴–목소리 연결 후 화자 카드에 얼굴을 보여 줌(v2) |
| 얼굴–목소리 잘못 연결 | 엉뚱한 사람이 강조됨 — 강조가 없는 것보다 나쁨 | 입 움직임 근거가 충분할 때만 연결, 확신 없으면 '화면 밖'처럼 자막만 표시 |
| 옆모습·작은 얼굴·자막·가림 | 얼굴을 못 찾아 강조 누락 | 사람 분할 윤곽은 몸 전체로 그림, 얼굴을 못 찾은 프레임은 강조 생략 |
| 처리 시간 증가 | CPU 서버에서 프레임 분석이 무거움 | 프레임 샘플링(얼굴 10fps·윤곽 5fps), 말하는 장면만 윤곽 계산 |

## 10. 다음 단계 (우선순위 순)

1. 실제 예능 클립 2~3개로 정성 평가 (출연자 수 입력)

4. 영상 사이에 사람 기억(같은 출연자를 다음 영상에서도 같은 이름으로)
