# SPEC-005 접근 제어

## 1. 배경과 문제

서버는 공인 IP로 열려 있고, 올린 영상은 저작권이 있는 예능일 수 있습니다. 시연 참가자만 들어오게 해야 합니다. 처음에 쓴 nginx Basic 인증은 일부 브라우저(내장 브라우저)가 주소의 자격 증명을 버려 401이 났습니다.

## 2. 목표 / 하지 않는 것

- 목표: 비밀번호 하나로 들어오는 단순한 로그인, 영상 파일까지 보호, 스크립트(curl)용 접근.
- 하지 않는 것: 회원가입, 사용자별 권한, OAuth, HTTPS(도메인이 생기면 별도 스펙).

## 3. 사용자 시나리오

1. 시연 참가자가 주소로 들어오면 로그인 화면이 뜨고, 안내받은 비밀번호를 넣으면 원래 가려던 페이지로 간다.
2. 7일 동안은 다시 묻지 않는다.
3. 로그인하지 않은 사람이 영상 주소(`/media/...`)를 직접 열면 401.
4. 운영자는 `curl -u x:<비밀번호>`로 API를 부른다.

## 4. 요구사항

| ID | 요구사항 |
| --- | --- |
| FR-AUTH-01 | 공유 비밀번호 로그인, 서명 쿠키 7일, 실패 시 1초 지연 |
| FR-AUTH-02 | 공개 경로 외 보호(API 401, 페이지는 로그인으로) |
| FR-AUTH-03 | 미디어는 nginx auth_request + 경로 화이트리스트 |
| FR-AUTH-04 | Basic 인증 허용 |
| FR-AUTH-05 | 로그아웃 |
| FR-AUTH-06 | 비밀번호가 없으면 개발 모드 |
| NFR-SEC-02·03 | 네트워크 제한, 경로 조작 방지 |

## 5. 수용 시나리오

```gherkin
시나리오: 로그인 없이 API 호출
  만일 쿠키 없이 GET /api/jobs 를 부르면
  그러면 401 {"detail": "로그인이 필요합니다"} 이다

시나리오: 다른 사이트로 보내기 시도
  만일 next=//evil.example 로 로그인하면
  그러면 / 로 이동한다
```

## 6. 영향과 위험

- HTTP라서 비밀번호가 평문으로 전송됨 → 시연 전용 비밀번호, 공개 저장소에 주소·비밀번호를 쓰지 않음.
