# SPEC-001 작업 접수와 대기열

## 1. 배경과 문제

자막을 만드는 데 영상 길이의 1배 넘는 시간이 걸립니다. 사용자는 올려 두고 페이지를 닫아도 처리가 이어져야 하고, 지금 어디까지 됐는지 알아야 합니다. 서버는 GPU 없는 한 대라서 무거운 작업을 동시에 여러 개 돌리면 모두 느려집니다.

## 2. 목표 / 하지 않는 것

- 목표: 업로드 → 대기열 → 한 건씩 처리 → 진행 상태·실패 이유 표시. 서버가 재시작돼도 작업을 잃지 않음.
- 하지 않는 것: 여러 워커 병렬 처리, 사용자별 작업 분리, 업로드 이어 받기.

## 3. 사용자 시나리오

1. 사용자가 5분짜리 예능 클립을 끌어 놓고 출연자 수 4명을 고른 뒤 '자막 만들기'를 누른다.
2. 업로드 진행률이 끝나면 작업 화면으로 넘어가 '음성 인식 → 화자 구분 …' 단계와 진행률을 본다.
3. 창을 닫았다가 홈의 '최근 작업'에서 다시 들어가 결과를 본다.
4. 소리 없는 화면 녹화를 올리면 "소리(오디오 트랙)가 없는 파일입니다."가 뜬다.

## 5. 수용 시나리오

```gherkin
시나리오: 허용하지 않는 형식
  만일 사용자가 "notes.txt"를 올리면
  그러면 400 "지원하지 않는 형식입니다: .txt"를 받고 작업은 만들어지지 않는다

시나리오: 처리 중 서버 재시작
  조건 작업이 running 상태다
  만일 워커가 재시작되면
  그러면 작업은 queued로 돌아가고 retries=1이 된다
  그리고 같은 일이 한 번 더 생기면 error가 된다
```

## 6. 영향과 위험

- 대기열이 길어지면 뒤 작업이 오래 기다립니다(단일 워커). 지금 규모에서는 허용.
