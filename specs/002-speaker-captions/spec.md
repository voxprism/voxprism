# SPEC-002 화자 구분 자막 생성

## 1. 배경과 문제

일반 자막은 말을 한 줄로 이어 받아 적을 뿐 누가 말했는지 표시하지 않습니다. 4~7명이 말하는 예능에서 청각장애인 시청자는 입 모양과 타이밍으로 화자를 추측해야 합니다. 화자가 바뀌어도 한 자막에 두 사람의 말이 섞이면 더 헷갈립니다.

## 2. 목표 / 하지 않는 것

- 목표: 단어마다 화자를 정하고, 화자가 바뀌면 자막을 나누고, 화자마다 색·이름표를 붙인다. 읽기 쉬운 길이·속도를 지킨다.
- 하지 않는 것: 얼굴로 화자 이름 자동 인식, 다국어, 실시간 처리.

## 3. 사용자 시나리오

1. 사용자가 3인 대화 영상을 올린다.
2. 결과 화면에 화자 카드 3장(S1~S3, 말한 시간 순)과 장면 썸네일·대표 대사가 나온다.
3. 자막은 `[화자 1] …`처럼 이름표와 화자 색으로 나오고, 한 자막에는 한 사람의 말만 있다.
4. CLOVA 키가 없는 개발 환경에서도 Whisper로 같은 흐름이 동작한다.

## 5. 수용 시나리오

```gherkin
시나리오: 턴 교대
  조건 A가 "오늘 뭐 먹지?"를 말하고 0.3초 넘게 쉰다
  만일 B가 "치킨 먹자"라고 말하면
  그러면 A와 B는 서로 다른 자막 이벤트가 되고 겹치지 않는다

시나리오: 동시에 말함
  조건 A가 말하는 중에 C의 말이 0.15초 이상 겹친다
  그러면 두 이벤트 모두 overlap=true 이고 화면에 함께 표시된다
```

## 6. 영향과 위험

- 출연자 수 자동 추정이 틀리면 두 사람이 한 화자로 합쳐집니다 → 업로드 화면에서 입력 권장, 화자 카드에서 '합치기'로만 되돌릴 수 있음(나누기는 불가).
- pyannote는 CPU에서 가장 오래 걸리는 단계입니다(약 40초/1분 영상).
